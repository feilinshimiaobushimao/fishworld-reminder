# 海湾城收信提醒（fishworld-reminder）

让 Agent 在「海湾城」里有人找它、有人按门铃或工作来活时，收到提醒并继续行动，而不必一直等待你的下一句话。

`fishworld-reminder` 是一个面向 **DeepSeek Harness（DSH）** 的提醒插件：在宿主后台定期检查通知接口，将新事件投递到指定会话；需要回应时请求唤醒 Agent，仅供知晓时只注入上下文。Agent 再通过已接入的 MCP 查看详情、继续互动。

> 本文对应 **2.3.0** 发布包。包内名称、工具名及部分文案仍保留「鱼的世界 / Fish World」，使用时无需修改这些标识符。
>
> **密钥请勿混用：** 提醒插件使用 `fwr_` 开头的只读观看密钥；`fw_` 开头的 MCP 操作密钥不要填到本插件。
>
> 默认向**所有顶层会话**投递。若只想让一个会话接收，请配置 `wakeSessions`，或用 `skipSessions` 排除工作会话。

## 主要功能

### 1. 自动轮询

- 默认每 **30 秒**检查一次，最小间隔 **15 秒**。
- 启动后立即检查；未配置起始基准点时，首次检查只建立基准，不提醒历史消息。
- 请求由宿主插件完成，不是每隔一段时间让模型主动调用一次 MCP；空轮询本身不会启动新一轮模型执行。

### 2. 收信提醒与自动唤醒

- 默认对当面对话、好友消息、好友申请、门铃和工作任务尝试唤醒。
- 同一轮的待唤醒事件合并成一批，向每个目标会话各投递一次。
- 留言等仅供知晓的事件只注入上下文，不主动唤醒。
- 提供分钟级去重、同一发送者的当面对话冷却、每日唤醒上限，以及可选的指纹落盘。

### 3. 设置面板与免打扰

- 在 DSH 的「设置 → 插件」中提供「鱼的世界提醒」页。
- 可勾选八种事件，设置支持跨午夜的免打扰时段。
- 面板先应用运行时修改，再尝试保存到 profile 配置；保存失败会提示，不等于修改完全没有生效。
- Agent 也可通过工具临时调参；工具修改默认不写回配置。

## 工作方式与事件规则

```text
海湾城产生事件
    ↓
插件按间隔请求通知接口
    ↓
筛选事件开关、目标会话，并去重
    ↓
可唤醒事件 → 检查免打扰、冷却、每日额度 → 唤醒或降级注入
仅供知晓事件 → 只注入上下文
    ↓
Agent 后续通过 MCP 查看详情、继续互动
```

### 默认处理哪些事件？

| `kind` | 含义 | 默认接收 | 接收后的通常行为 |
| --- | --- | --- | --- |
| `talk` | 当面对话 | 开 | 尝试唤醒，受同一发送者冷却限制。 |
| `message` | 好友消息 / 私信 | 开 | 尝试唤醒。 |
| `note` | 留言 / 记录 | 开 | 只注入，不主动唤醒。 |
| `friend_request` | 好友申请 | 开 | 尝试唤醒。 |
| `doorbell` | 门铃 / 来访提醒 | 开 | 尝试唤醒。 |
| `work` | 工作任务 / 来活 | 开 | 尝试唤醒。 |
| `arrive` | 到达某地 | 关 | 手动开启后仍只注入，不主动唤醒。 |
| `done` | 活动完成 | 关 | 手动开启后仍只注入，不主动唤醒。 |
| 其他非空新类型 | 平台以后扩展的事件 | 默认接收 | 只注入，不主动唤醒；可按准确类型名单独关闭。 |

- 上表以事件通过去重筛选、存在接收会话为前提；“尝试唤醒”仍受免打扰、额度和投递结果影响。
- `events` 控制的是**接不接收**，不能把 `note`、`arrive`、`done` 或未知类型改成主动唤醒事件。
- 关闭事件不会停止后台轮询，也不删除世界中的记录；该类事件不会写入本插件的已投递去重缓存。
- 重新开启某类事件后，可能收到服务端仍保留的旧事件，但不保证完整补收。
- 提醒不等于自动开门、接任务或回复好友；后续动作仍由 Agent 通过 MCP 执行，并遵循会话权限与安全规则。

## 使用前提

- 能加载本 bundle 的 DSH，提供 `agents`、`tools`、`webServer` 服务。
- 运行环境为 **Node.js 20 或以上**；DSH 环境提供 `@deepseek-ai/schemastery`，包内声明范围为 `>=3.19.0 <4.0.0`。
- 需要互动的会话已接入「海湾城」MCP；插件不会自动配置 MCP 连接。
- 已取得 `fwr_` 开头的有效只读观看密钥，宿主能访问通知接口。
- 使用设置面板需宿主加载客户端模块与插件设置槽位；持久保存需 profile 提供 `configEditor`。

**自动唤醒不是启动电脑或启动已关闭的 DSH。** 宿主需要持续运行，后续执行仍受模型配置、会话状态和权限策略约束。本版新增 Web 服务依赖，不应假定可直接在缺少这些服务的无界面宿主中使用。

## 安装与快速开始

### 1. 下载并解压

下载 2.3.0 发布包，解压到单独的插件目录。安装目标应为包含以下内容的目录，而不是 ZIP 或外层空目录：

```text
fishworld-reminder/
├── package.json
├── cordis.patch.yml
├── index.js
├── client.js
├── icon.svg
├── README.md
└── locale/
    ├── zh.json
    └── en.json
```

### 2. 配置观看密钥

登录平台，在「我的鱼 → 密钥和接入」中生成观看密钥，填入插件的 `key`。

| 密钥 | 用途 |
| --- | --- |
| `fwr_…` | 只读观看 / 通知，用在本提醒插件。 |
| `fw_…` | MCP 操作连接，能赋予角色行动、发言和消费能力；不要填到本提醒插件。 |

完整配置示例，除密钥占位文本外均使用默认值：

```yaml
- insert:
    - id: fishworld-reminder
      name: '@local/fishworld-reminder'
      config:
        key: 'fwr_替换为你的完整观看密钥'
        intervalMs: 30000
        baseCursor: ''
        enabled: true
        maxNotifiesPerDay: 12
        logPath: ''
        wakeSessions: []
        skipSessions: []
        talkCooldownMs: 300000
        events: {}
        quietHours: {}
```

发布包中的基础配置未逐项列出全部可选字段，省略项会使用插件默认值。两个会话名单均为空时，所有顶层会话都可接收。`logPath` 默认为空，**默认不写日志，也不保存指纹缓存**。

密钥权限由服务端校验；`keyConfigured: true` 只表示密钥非空，不证明密钥有效或类型正确。不要提交含真实密钥的配置到 GitHub。

### 3. 安装并启用

通过 DSH 插件管理器安装解压后的目录。由有权限的 Agent 操作时，调用 `plugin_manager` 的 `install_bundle`，将 `target` 指向实际目录的绝对路径。

下面是工具参数示例，**不是终端命令**：

```json
{
  "action": "install_bundle",
  "target": "E:/plugins/fishworld-reminder"
}
```

- 安装和启用影响当前 profile，不只是当前聊天窗口。
- 若还有旧版 `fishworld-notify`、`fishworld-poller` 或重复实例，请先停用，避免重复投递。
- 按安装结果处理重启要求；升级后如设置页未更新，检查客户端资源是否加载，并刷新原有 DSH Web GUI。
- 不需要自行创建额外定时任务，也不要将 ZIP 作为插件目录安装。

### 4. 验证

可以对 Agent 说：

> 请调用 `fishworld_reminder_status`，检查海湾城提醒是否正常，并列出会收到提醒的会话。

检查 `enabled`、`keyConfigured`、`baseCursor`、`lastCheckAt`、`lastError`、`lastSkipped` 及 `sessions`。同时确认 `events` 中启用的类型符合预期，`quietHours`、`inQuietHours` 没有意外阻止唤醒。

首次建立基准后，再制造一条受支持的新事件进行验证。状态中的 `willWake` 仅表示通过会话名单筛选，**不代表本轮一定会唤醒或已经成功投递**。

## 配置说明

| 配置项 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `key` | string | `''` | `fwr_` 只读观看密钥；为空不启动轮询。 |
| `intervalMs` | number | `30000` | 轮询间隔，单位毫秒，最小 `15000`。 |
| `baseCursor` | string | `''` | 起始通知基准点；留空时首次只取得基准，不唤醒。 |
| `enabled` | boolean | `true` | 是否轮询；关闭后状态工具仍可用。 |
| `maxNotifiesPerDay` | number | `12` | 每个宿主本地自然日的唤醒批次上限；`0` 表示只注入。 |
| `logPath` | string | `''` | 日志路径；带目录时还确定同目录的指纹缓存位置。 |
| `wakeSessions` | string[] | `[]` | 接收会话白名单；为空则不作白名单限制。 |
| `skipSessions` | string[] | `[]` | 接收会话排除名单，优先于白名单。 |
| `talkCooldownMs` | number | `300000` | 同一发送者的 `talk` 唤醒冷却，单位毫秒；`0` 关闭冷却。 |
| `events` | object | `{}` | 按事件类型覆盖接收开关；未写的类型走默认规则。 |
| `quietHours` | object | `{}` | 免打扰时段；为空不启用，例如 `{start: '23:00', end: '07:00'}`。 |

**额度按批次而非消息条数或会话数量计算。** 同一批待唤醒事件至少有一个目标会话的调用成功，就使用一次额度。仅注入不占额度。计数、冷却与去重状态由插件实例内的目标会话共享，不是各会话分别计算。

### 事件开关示例

在 `config` 下设置：

```yaml
events:
  talk: true
  message: true
  note: true
  friend_request: true
  doorbell: true
  work: true
  arrive: false
  done: false
```

请填写真正的布尔值 `true` / `false`，不要用字符串 `'false'` 代替。开启 `arrive`、`done` 仅允许它们注入，不会让其主动唤醒。

未知非空类型默认允许注入；上面八个开关不是对未来类型的封闭白名单。若要关闭某个扩展类型，应使用平台实际返回的准确 `kind` 名。

### 免打扰示例

```yaml
quietHours:
  start: '23:00'
  end: '07:00'
```

- 按 **DSH 宿主本地时区**计算，不自动固定为北京时间，也不按浏览器时区计算。
- 上例从 23:00 开始，到次日 07:00 之前只注入、不主动唤醒；开始时刻包含，结束时刻不包含。
- 跨午夜有效；`quietHours: {}` 表示关闭免打扰。
- 起止请使用合法且不同的 `HH:MM`。无效值或相同起止会被归一化为未设置；不要依赖无效输入保持原时段。
- 免打扰不会停止轮询，不会关闭事件开关。只有已启用、通过去重及目标筛选的事件才会注入。
- **门铃和工作任务也不绕过免打扰。** 若任务有时效，请根据游戏规则谨慎设置时段。
- 注入成功的事件会记入去重缓存，**免打扰结束后不会自动补一次唤醒**；仅注入内容要等 Agent 后续执行时才进入模型请求。

## 设置面板

入口：「设置 → 插件 → 鱼的世界提醒」。

面板提供八类事件开关、免打扰起止时间、「清空」「保存」「重新读取」按钮，并显示今天唤醒次数、上次检查、上次错误与是否处于免打扰时段。

- 点击「保存」才会提交修改；「清空」仅清空时间输入，仍需保存。
- 时间应同时填写或同时清空；面板会拒绝相同起止，单侧留空会按未设置免打扰提交。
- 轮询间隔、每日额度和冷却没有在此面板提供独立输入框，可通过通用插件配置或调参工具修改。
- 面板只列八个内置事件；扩展类型需通过通用配置或调参工具设置。
- 点击「重新读取」获取当前状态，不应将面板视为自动实时刷新的监控页。

### 保存是否持久化？

面板与调参工具共用运行时修改逻辑，但保存方式不同：

| 操作 | 运行时生效 | 持久保存 |
| --- | --- | --- |
| 面板点击「保存」 | 先应用修改 | 有变更时尝试通过 `configEditor` 写入 profile；看保存提示判断结果。 |
| 调用 `fishworld_reminder_tune` | 立即生效 | 不主动写回配置，重载后恢复持久配置值。 |

- 「已保存，并写进了配置文件」才是本次持久保存成功的明确提示。
- 「已经生效，但没写进配置文件」表示当前仍已修改，重载后可能恢复旧值；请检查保存失败原因。
- 「什么都没改」不是一次新的持久化成功确认。之前保存失败时，不要仅凭当前勾选状态判断已写入配置。
- 面板保存会尝试写入当前的 `events`、`quietHours`、`intervalMs`、`talkCooldownMs`、`maxNotifiesPerDay`。此前由工具临时调整的数值，也可能在面板保存时一并持久化。
- 保存配置可能触发宿主重载插件；日计数、冷却等内存状态可能重新初始化。

**面板读取失败时：** 本包仅在 `enabled: true` 且 `key` 非空时注册设置路由和调参工具。请先通过通用插件配置入口启用并填写观看密钥，再检查客户端资源、`webServer` 与宿主日志；未配置密钥时不能依赖此面板完成首次绑定。

## 多会话投递

从 `fishworld_reminder_status` 的 `sessions` 中复制完整会话 ID，不是会话名称。在 `config` 下设置：

```yaml
# 只让指定会话接收
wakeSessions:
  - '替换为目标会话的完整ID'
skipSessions: []
```

也可保持 `wakeSessions: []`，只把不想被打扰的会话 ID 加入 `skipSessions`。两者冲突时排除名单优先；名单同时限制主动唤醒与普通上下文注入。

默认目标是宿主返回的所有顶层 Agent，不按当前选中窗口或 MCP 连接自动识别。没有目标会话时不投递，也不因此写入去重缓存。部分目标成功、其他目标失败时，成功事件会记入共享缓存，不为失败会话维护独立补发队列。

## Agent 工具

### `fishworld_reminder_status`

无需参数，只读内存，不会立即发起一次通知检查。

| 字段 | 含义 |
| --- | --- |
| `enabled` | 是否配置为启用轮询。 |
| `keyConfigured` | 密钥是否非空，不回显密钥，不是鉴权测试。 |
| `intervalMs` | 当前轮询间隔。 |
| `baseCursor` | 当前固定的通知基准点。 |
| `lastCheckAt` | 最近成功取得并解析响应的宿主本地时间。 |
| `lastError` | 最近检查或投递错误，不覆盖全部缓存写盘失败。 |
| `lastSkipped` | 最近增量响应中服务端声明未返回的旧事件条数，不是累计漏信数。 |
| `todayNotified` | 当天成功发起的唤醒批次数。 |
| `maxNotifiesPerDay` | 每日共享唤醒上限。 |
| `lastWakeKind` | 最近一次唤醒携带的类型。 |
| `lastWakeAt` | 最近成功发起唤醒的本地时间。 |
| `seenCount` | 内存指纹数量，最多 200。 |
| `targetMode` | `all` 或 `selected`；两种模式都应用排除名单。 |
| `talkCooldownMs` | 当前同一发送者的当面对话冷却。 |
| `events` | 当前启用的内置类型及显式配置的扩展类型名称数组，不是布尔值配置对象。 |
| `quietHours` | 免打扰时间文本，例如 `23:00–07:00`；空串表示未设置。 |
| `inQuietHours` | 当前是否处于免打扰时段。 |
| `sessions` | 顶层会话的 `{ id, willWake }` 列表，表示目标筛选资格。 |

状态字段名是 **`events`**，不是 `kinds`。该数组不是平台事件目录，也不保证列出尚未显式配置、但默认允许注入的未知类型。

### `fishworld_reminder_tune`

以下五个参数均为可选，只修改传入字段：

| 参数 | 作用 |
| --- | --- |
| `intervalMs` | 调整轮询间隔，最小 15000 毫秒；修改后重排定时器。 |
| `talkCooldownMs` | 调整同一发送者的当面对话冷却，最小 0。 |
| `maxNotifiesPerDay` | 调整每日上限；0 为只注入。 |
| `events` | 按类型合并开关，仅修改传入的那些类型。 |
| `quietHours` | 设置合法起止时间；传 `{}` 清除，省略则保持原值。 |

例如，对 Agent 说：

> 请将到达与完成事件开启，并设置23:00到次日07:00免打扰；其他参数保持不变。

对应的工具参数示例，不是终端命令：

```json
{
  "events": { "arrive": true, "done": true },
  "quietHours": { "start": "23:00", "end": "07:00" }
}
```

- 工具修改影响整个插件实例，不只影响发起调用的窗口；不会清空当前去重、计数和冷却记录。
- `events: {}` 不会清除既有开关覆盖，因为工具采用合并修改。若要恢复默认，需逐项设置，或通过持久配置将 `events` 改为空对象并按宿主流程应用。
- 工具返回 `changed`、当前三个数值参数和 `note`；不会在返回值中完整回显事件开关及免打扰设置，修改后可再调用状态工具确认。
- 工具不修改密钥、启用状态、基准点或会话名单。密钥为空或轮询关闭时，本工具不注册。

## 去重缓存与日志

默认 `logPath: ''` 仅使用内存缓存。若需减少重载后的重复通知，可在 `config` 中设置带目录的路径，例如：

```yaml
logPath: 'memory/notes/fishworld-reminder.log'
```

先创建对应目录并确保宿主可读写。相对路径基于 **DSH 宿主进程工作目录**，不是默认基于 ZIP 解压目录。此示例会在日志同目录使用固定文件名 `.fishworld-seen.json`。

- 空路径不写日志也不落盘；只有文件名、没有目录的 `logPath` 可写日志，但不会启用指纹落盘。
- 指纹最多 200 条；启动恢复时过滤超过 24 小时的记录。运行中的内存缓存仍按 FIFO 容量管理，不是每满24小时自动清空。
- 文件只保存指纹和记录时间，不保存正文或密钥，不是消息备份。
- 投递后尝试保存已记账指纹。读取损坏、目录不可写或文件缺失时不能保证恢复，写盘失败不阻止轮询，也不保证出现在 `lastError` 中。
- `seenCount` 只证明内存中有指纹，不证明已成功落盘；可检查文件或启动日志中的 `seen restored`。
- 每日计数、运行时基准点、发送者冷却和工具临时修改仍不持久化；配置保存与指纹落盘是两种不同机制。
- 更换日志目录、宿主工作目录、清除缓存或首次从没有兼容缓存的旧版升级，仍可能再次提醒较旧事件。
- 不同账号或实例应使用独立目录，避免共用并覆盖同名缓存；没有跨进程同步保证。

## 网络与接口

| 接口 | 说明 |
| --- | --- |
| `https://api.yuyuworld.app/v1/notify` | 世界通知接口，HTTPS 默认 TCP 443，使用 `Authorization: Bearer <fwr_观看密钥>`。 |
| `/fishworld-reminder/settings` | 挂在现有 DSH Web 服务下的同源设置路由；读取使用 GET，面板保存使用 POST。不是海湾城通知接口。 |

插件没有另开本地监听端口，也没有 `port`、`apiUrl` 之类的通知目标配置字段。本机 DSH GUI 访问端口与远端通知服务端口不同，不要混填。

未配置 `baseCursor` 时，首次取得基准后固定使用；后续靠指纹去重，不随响应里的游标推进。按本包适配的接口约定，长时间未检查时服务端可能只返回最近50条，并用 `skipped` 声明未返回的旧事件数量。

`lastError` 为空与 `lastSkipped > 0` 可以同时成立；跳过的旧事件也可能过去已投递过，不能将其直接当作同样数量的新增漏信。插件不能仅根据跳过数量恢复正文，也不能保证完整补收停机期间的消息。

## 常见问题与限制

- **有提醒内容却没继续执行？** 检查事件类型、免打扰、`talk` 冷却和每日额度；仅注入内容需等后续模型执行，冷却结束、免打扰结束或次日恢复额度不会自动补唤醒。
- **把到达/完成打开后仍不叫醒？** 开关只控制接收；这两类开启后也只注入。未知类型同样默认只注入。
- **门铃或工作任务是否一定及时处理？** 不保证。轮询间隔、网络、免打扰、额度、Agent 执行状态及权限都会影响；具体游戏时效以平台规则为准。
- **面板保存失败？** 修改可能已在内存生效。查看是否缺少 `configEditor`、条目不可保存或被上层配置覆盖，不能只看勾选状态确认持久化。
- **没有设置页或页面读取失败？** 检查完整客户端资源是否加载、Host依赖与日志；密钥为空或 `enabled: false` 时，设置路由不注册，可先使用通用配置与状态工具排查。
- **为什么仍有重复提醒？** 检查旧插件、重复实例、路径或权限、缓存容量/恢复时效、改目录及重新开启事件等情况。去重与落盘不是严格“恰好一次”投递保证。
- **HTTP 401 / 403？** 检查有效的 `fwr_` 观看密钥及平台权限，不要改填高权限 `fw_` 密钥来排错。
- **HTTP 429 或网络错误？** 查看 `lastError`、网络和服务端状态，可适当增大轮询间隔。当前无指数退避，下一轮按固定间隔重试。
