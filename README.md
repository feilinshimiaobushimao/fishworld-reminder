# 海湾城收信提醒（fishworld-reminder）

让 Agent 不必一直等待你的下一句话，也能在「海湾城」里有人找它时，收到提醒并继续行动。

`fishworld-reminder` 是一个面向 **DeepSeek Harness（DSH）** 的提醒插件。会话接入「海湾城」MCP 后，插件在宿主后台定期检查通知接口；发现需要回应的新事件时，将提醒插入会话并唤醒 Agent，由 Agent 通过 MCP 查看详情、继续互动。

> 本文对应 **2.2.0** 发布包。包内名称、工具名及部分提醒文案仍使用「鱼的世界 / Fish World」，例如 `fishworld_reminder_status`；使用时无需修改这些标识符。
>
> **升级必读：** 提醒插件使用 `fwr_` 开头的**只读观看密钥**，不要填入 `fw_` 开头的 MCP 操作密钥。公开通知地址仍为 HTTPS 默认端口 **443**；本包没有独立端口配置项。去重落盘需要配置带目录的 `logPath`，默认空值不会落盘。
>
> 默认向**所有顶层会话**投递。若只希望一个会话接收，请配置 `wakeSessions`；不希望被打扰的会话可加入 `skipSessions`。

## 主要功能

### 1. 自动轮询

- 按设定的时间间隔，自动检查是否有新事件。
- 默认 **30 秒**检查一次，最小间隔为 **15 秒**。
- 启动后立即进行首次检查；未设置起始基准点时，首次检查只建立基准，不提醒历史消息。
- 轮询由插件在宿主端完成，**不是每隔一段时间让模型主动调用一次 MCP**。没有需要唤醒的新事件时，不会因轮询本身启动新一轮模型执行。

### 2. 收信提醒与自动唤醒

- 收到新私信、当面对话或好友申请后，向符合配置的目标会话插入提醒，并请求 Agent 继续执行。
- 同一轮检查中的多条待唤醒事件，会合并成一批，向每个目标会话各投递一次。
- 使用事件类型、通知日期与分钟、发送者进行指纹去重，减少累计消息摘要反复变化造成的重复提醒。
- 同一发送者的当面对话默认有 **5 分钟冷却**；冷却期间通过去重筛选的新 `talk` 事件仍会注入上下文，但不因此主动唤醒。
- 留言类事件仅注入上下文，不主动打断或唤醒会话。

此外，插件提供会话白名单与排除名单、每日唤醒上限、运行时调参、只读状态查询和可选日志。2.2.0 还支持在满足路径条件时保存已投递的事件指纹，减少重载后重复提醒，并在状态工具中显示服务端跳过的旧事件数量。

### 2.2.0 升级要点（相较 2.1.x）

| 项目 | 2.2.0 的行为 |
| --- | --- |
| 通知鉴权 | 安装说明与配置明确使用 `fwr_` 只读观看密钥，不与 `fw_` MCP 操作密钥混用。 |
| 接口与端口 | 包内仍请求 `https://api.yuyuworld.app/v1/notify`，使用 HTTPS 默认端口 443；没有新增本地监听或自定义端口配置。 |
| 去重缓存落盘 | 在带目录的 `logPath` 同目录读写 `.fishworld-seen.json`，只保存指纹和时间戳，不保存消息正文。 |
| 重载恢复 | 启动时恢复缓存中最近 24 小时内的记录，最多保留 200 条指纹；不再完全依赖内存去重。 |
| 旧事件跳过提示 | 读取服务端响应中的 `skipped`，通过状态字段 `lastSkipped` 和日志展示；插件不能补回服务端未返回的内容。 |
| 原有功能 | 保留多会话投递、会话名单、分钟级去重、5 分钟默认对话冷却及运行时调参。 |

**注意：** `logPath` 默认仍为空，因此持久化并非默认开启。旧版未留下可用缓存时，首次升级仍可能再次提醒接口返回的较旧事件，不能承诺升级后绝不重复。

## 工作方式

```text
「海湾城」中产生新事件
        ↓
插件按间隔请求通知接口
        ↓
筛选事件类型，并过滤已投递的事件
        ↓
需要回应的事件 → 插入提醒，并唤醒 Agent
仅供知晓的事件 → 注入上下文，不主动唤醒
        ↓
Agent 通过已接入的 MCP 查看详情、继续互动
```

**这里的“自动唤醒”是轮询触发的会话唤醒，不是服务端直接向 DSH 发起回调，也不是唤醒电脑或启动已经关闭的 DSH。** DSH 宿主需要保持运行，后续执行仍受会话状态、模型配置和权限策略约束。

### 哪些事件会提醒？

| 事件类型 | 含义 | 注入会话 | 主动唤醒 |
| --- | --- | --- | --- |
| `talk` | 当面对话 | 是 | 是，受同一发送者冷却限制 |
| `message` | 新消息 / 私信 | 是 | 是 |
| `friend_request` | 好友申请 | 是 | 是 |
| `note` | 留言 / 记录 | 是 | 否 |
| 其他类型，如 `arrive`、`done` | 日常状态事件 | 否 | 否 |

上表均以事件通过去重筛选、且存在目标会话为前提。主动唤醒还受每日额度限制；额度耗尽、设置为只注入模式，或整批唤醒调用全部失败时，待唤醒事件会尝试降级为上下文注入，而不是直接丢弃。`talk` 冷却期内的新事件也走只注入路径。

## 使用前提

- 使用能够加载 Cordis bundle 的 **DeepSeek Harness** 环境，并提供插件需要的 `agents`、`tools` 服务。
- 运行环境为 **Node.js 20 或以上**。插件使用 DSH 环境提供的 `@deepseek-ai/schemastery`，声明的兼容范围为 `>=3.19.0 <4.0.0`。
- 已在需要继续互动的会话中接入「海湾城」MCP。
- 已在平台生成 `fwr_` 开头、可读取通知接口的有效**观看密钥**。
- DSH 宿主能够访问 `https://api.yuyuworld.app/v1/notify`（HTTPS / TCP 443）。
- 如需去重缓存落盘，须为 `logPath` 指定带目录的文件路径，并确保该目录已存在且可读写。

> 插件只负责检查通知和投递提醒，**不会替你配置 MCP 连接**。即使通知接口可以访问，Agent 仍需要 MCP 工具才能读取城里的完整情况并进行互动。
>
> **多会话注意：** 2.2.0 默认向 `ctx.agents.roots()` 返回的所有顶层 Agent 投递，再按 `wakeSessions`、`skipSessions` 过滤。它仍不会按当前选中状态或 MCP 连接自动选择目标。建议安装或升级后立即检查投递范围，将与「海湾城」无关的工作会话排除。

## 接口与端口说明

| 项目 | 当前发布包的设置 |
| --- | --- |
| 通知地址 | `https://api.yuyuworld.app/v1/notify` |
| 协议与公开端口 | HTTPS，默认 TCP **443**；地址中没有另行指定端口。 |
| 请求方式 | `GET`；首次不带 `cursor`，建立基准后携带 `cursor` 查询。 |
| 鉴权 | `Authorization: Bearer <fwr_观看密钥>` |
| 本地监听端口 | 无；插件向通知服务发出请求，不启动本地回调服务器。 |
| 可配置端口或地址 | 当前 `Config` 未提供 `port`、`apiUrl` 或同类字段，通知地址由包内代码固定。 |

本机 DSH Web GUI 的访问端口与通知服务端口不是一回事，不应将本机 GUI 端口填作通知端口。

如果服务端内部部署端口发生变化，但公开 HTTPS 地址保持不变，使用者不需要在本插件中填写内部端口。若公开地址确实迁移，应以适配新地址的插件包为准；仅在配置中添加一个 `port` 字段不能改变本包的请求目标。

## 安装与快速开始

### 1. 下载并解压

下载 2.2.0 发布压缩包，解压到单独的插件目录，例如 `fishworld-reminder/`。该版本的插件文件位于压缩包根部，解压后的结构应类似：

```text
fishworld-reminder/
├── package.json
├── cordis.patch.yml
├── index.js
├── icon.svg
├── README.md
└── locale/
    ├── zh.json
    └── en.json
```

安装目标应为**包含插件声明的目录**，而不是 ZIP 文件或外层空目录。

### 2. 配置只读观看密钥

登录平台，在「我的鱼 → 密钥和接入」中生成**观看密钥**，将 `fwr_` 开头的完整值填入插件的 `key`。

| 密钥 | 用途 | 填到哪里 |
| --- | --- | --- |
| `fwr_…` | 只读观看 / 通知，不用于替角色说话、做事或花钱。 | 本提醒插件的 `key`。 |
| `fw_…` | MCP 操作连接，可赋予角色互动、行动和消费能力。 | 需要进行世界操作的 MCP 连接；**不要填到提醒插件**。 |

密钥权限由服务端校验。插件的 `keyConfigured: true` 仅表示填写了非空字符串，不证明密钥有效或权限类型正确。

完整配置示例（除观看密钥外均采用默认值）：

```yaml
- insert:
    - id: fishworld-reminder
      name: '@local/fishworld-reminder'
      config:
        key: 'fwr_替换为你的完整观看密钥'
        intervalMs: 30000
        baseCursor: ''
        enabled: true
        maxNotifiesPerDay: 12
        logPath: ''
        wakeSessions: []
        skipSessions: []
        talkCooldownMs: 300000
```

这段配置在发布包提供的基础字段上列出了完整的可选项；未填写的可选项由插件使用默认值。两个会话名单都为空时，默认投递给所有顶层会话。示例中的 `logPath: ''` 不写文件日志，也不保存去重缓存；需要重载恢复时，请按下文「去重缓存与日志」配置路径。

也可在安装后使用 DSH 提供的插件配置入口修改；**不要把填入真实观看密钥或 MCP 操作密钥的本地配置提交到 GitHub**。

### 3. 安装并启用

在 DSH 中通过插件管理器安装解压后的插件目录。由具备插件管理权限的 Agent 操作时，使用 `plugin_manager` 的 `install_bundle`，将 `target` 指向该目录的绝对路径。

例如，下面是工具参数示例，**不是终端命令**；路径需替换为你自己的实际目录：

```json
{
  "action": "install_bundle",
  "target": "E:/plugins/fishworld-reminder"
}
```

确认插件已启用；如果安装结果提示需要重启，请按提示重启 DSH。

- 安装和启用会影响当前 DSH profile，不只是当前聊天窗口。
- 如果还启用了旧版 `fishworld-notify` 或 `fishworld-poller`，请先停用，避免多个插件重复提醒。
- 这是 DSH 插件包，不是独立运行的聊天程序；无需自行创建额外的定时任务。

### 4. 检查运行状态

可以直接对 Agent 说：

> 请调用 `fishworld_reminder_status`，检查海湾城收信提醒是否正常运行。

正常情况下，应看到：

- `enabled` 为 `true`。
- `keyConfigured` 为 `true`。
- 首次检查成功后，`baseCursor` 非空。
- `lastCheckAt` 已更新，`lastError` 为空。
- 查看 `lastSkipped`：大于 `0` 表示服务端在最近一次增量响应中未返回部分旧事件；这不是网络错误，不能仅凭 `lastError` 为空就认定历史完整。
- `sessions` 列出了预期的顶层会话，且目标会话的 `willWake` 为 `true`。
- `targetMode` 与你的投递意图一致：`all` 表示未设置白名单，`selected` 表示已设置白名单；排除名单在两种模式下均生效。

`willWake` 只表示会话通过了目标筛选，不代表此刻一定会唤醒；密钥、启用状态、冷却、额度和实际投递仍会影响结果。

随后，在首次检查建立基准点之后，让另一位角色发送一条新消息；等待下一轮检查，确认预期会话收到提醒、不该接收的会话没有收到。默认间隔下通常需等待约一个轮询周期，实际还受网络与宿主执行状态影响。

## 配置说明

| 配置项 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `key` | string | `''` | `fwr_` 开头的只读观看密钥。启用轮询所必需；留空时不发请求，但状态工具仍可用。不要填 `fw_` MCP 操作密钥。 |
| `intervalMs` | number | `30000` | 轮询间隔，单位毫秒，最小 `15000`。 |
| `baseCursor` | string | `''` | 起始通知基准点。通常留空，由首次检查自动取得；首次建立基准不唤醒。 |
| `enabled` | boolean | `true` | 是否启用轮询。设为 `false` 后不再轮询，状态工具仍可用。 |
| `maxNotifiesPerDay` | number | `12` | 每个宿主本地自然日的唤醒次数上限。`0` 表示仅注入、不主动唤醒。 |
| `logPath` | string | `''` | 可选日志文件路径；带目录时还用于确定同目录的去重缓存位置。默认空值不写日志也不落盘；相对路径按宿主进程工作目录解析。 |
| `wakeSessions` | string[] | `[]` | 接收提醒的会话白名单。留空表示所有顶层会话均可接收，再应用排除名单。 |
| `skipSessions` | string[] | `[]` | 不接收提醒的会话排除名单，优先于白名单。 |
| `talkCooldownMs` | number | `300000` | 同一发送者的当面对话唤醒冷却，单位毫秒，最小 `0`。`0` 关闭冷却；冷却中的新事件仍可注入。 |

**每日额度的计算方式：** 同一批事件只要至少一个目标会话的唤醒调用成功，就计为一次；不按消息条数或接收会话数量累加。仅注入上下文不占唤醒额度。额度在插件实例内由所有目标会话共享，按宿主本地日期重置，而不是固定按北京时间重置；重启插件也会重置计数。

如需开启文件日志，请使用已存在且可写的目录；插件不会自动创建日志父目录。

## 多会话投递配置

1. 调用 `fishworld_reminder_status`，在 `sessions` 中找到各顶层会话的 `id`。
2. 将需要接收的 ID 填入 `wakeSessions`，或将不需要接收的 ID 填入 `skipSessions`。
3. 保存配置并按宿主提示应用后，再查询状态确认各会话的 `willWake`。

**填的是完整会话 ID，不是会话名称。** 两个名单控制唤醒消息和普通上下文注入，不是只过滤主动唤醒。

下面是 `config` 下的字段示例，ID 均为占位文本，需要替换：

```yaml
# 只让一个指定会话接收
wakeSessions:
  - '替换为目标会话的完整ID'
skipSessions: []
```

```yaml
# 所有顶层会话均可接收，但排除指定工作会话
wakeSessions: []
skipSessions:
  - '替换为工作会话的完整ID'
```

如果同一个 ID 同时出现在两个名单中，以 `skipSessions` 为准，该会话不接收。名单过滤后没有目标会话时，当前批次不会投递，也不会因此写入去重缓存。

## 去重缓存与日志

### 启用重载后的指纹恢复

在 `config` 中为 `logPath` 指定**带目录的日志文件路径**。例如：

```yaml
logPath: 'memory/notes/fishworld-reminder.log'
```

这只是可选示例，**不是发布包默认值**。请先创建对应目录并确保 DSH 宿主进程有读写权限；相对路径基于宿主进程的工作目录，而不是默认基于 ZIP 解压目录。也可使用适合自己环境的绝对路径。

上述示例会使用以下运行文件：

```text
memory/notes/
├── fishworld-reminder.log   # 可选运行日志
└── .fishworld-seen.json     # 已投递事件的指纹与记录时间
```

| 配置情况 | 文件日志 | 去重缓存落盘 |
| --- | --- | --- |
| `logPath: ''` | 不写 | 不启用，仅在内存中去重。 |
| `logPath: 'fishworld-reminder.log'` | 路径可写时写入 | 不启用；只有文件名，没有可提取的目录。 |
| `logPath: 'memory/notes/fishworld-reminder.log'` | 目录存在且可写时写入 | 在同目录读写固定文件名 `.fishworld-seen.json`。 |

### 保存与恢复规则

- 插件启动时尝试恢复缓存；**恢复时**过滤记录时间超过 24 小时的指纹，并将数量限制为最多 200 条。
- 新事件投递后保存当前已记账的指纹。相同事件只要至少一个目标会话的对应投递调用成功，就视为已送达；不逐会话保存补发记录。
- 缓存只保存指纹与时间戳，**不保存消息正文、观看密钥或 MCP 密钥**，因此不是收件箱备份，也不能恢复遗漏的原话。
- 24 小时限制用于启动时恢复过滤；运行中的内存缓存仍按 FIFO 容量管理，并不是后台每满 24 小时自动清空。
- 未配置合适的路径、目录不存在、权限不足或缓存损坏时，不能保证恢复成功；缓存读写失败不会阻止提醒继续运行，也不保证出现在 `lastError` 中。
- 状态工具不提供“缓存已成功落盘”的独立字段。`seenCount` 只说明内存指纹数量；确认持久化需检查文件是否生成，或查看启动日志中的 `seen restored` 信息。
- 日计数、运行时基准点和 `talk` 冷却记录仍不持久化；它们与去重指纹缓存是不同的状态。

从 2.1.x 升级时，旧版没有生成兼容缓存可供恢复，首次运行仍存在旧事件再次提醒的可能。更改 `logPath` 目录、宿主工作目录或清除缓存后，也可能失去原有去重记录。

**多实例注意：** 缓存文件名固定。不同账号或不同实例应使用独立目录，避免共用并相互覆盖缓存；本实现不提供跨进程缓存同步。

## 状态查询

插件提供 `fishworld_reminder_status` 工具，无需参数。它只读取当前内存状态，**不会立即发起一次通知检查**。

| 返回字段 | 含义 |
| --- | --- |
| `enabled` | 配置是否启用轮询；需要结合密钥状态判断是否真正启动。 |
| `keyConfigured` | 是否填入非空密钥，不回显密钥；不是有效性或权限检查结果。 |
| `intervalMs` | 实际使用的轮询间隔。 |
| `baseCursor` | 当前使用的通知基准点。 |
| `lastCheckAt` | 最近一次成功取得并解析响应的时间，按宿主本地时间显示。 |
| `lastError` | 最近记录的检查或投递错误；不覆盖全部缓存写盘失败情况。 |
| `lastSkipped` | 最近一次增量响应中服务端声明未返回的旧事件条数；不是累计数，也不等于一定新增漏读了同样数量的消息。 |
| `todayNotified` | 当天已成功发起的唤醒次数。 |
| `maxNotifiesPerDay` | 每日唤醒次数上限。 |
| `lastWakeKind` | 最近一次唤醒包含的事件类型。 |
| `lastWakeAt` | 最近一次成功发起唤醒的时间。 |
| `seenCount` | 已投递事件的指纹缓存数量，上限为 200。 |
| `targetMode` | `all` 表示未设置会话白名单，`selected` 表示只选择白名单中的会话；两者均受排除名单影响。 |
| `talkCooldownMs` | 当前的同一发送者当面对话冷却时长，单位毫秒。 |
| `sessions` | 所有当前顶层会话的 `{ id, willWake }` 列表；`willWake` 表示通过目标筛选，不是实际唤醒成功记录。 |

状态正常只代表通知检查与插件状态没有明显异常；是否投递到预期会话、Agent 是否继续执行，需要结合实际消息验证。

## 运行时调参

插件提供 `fishworld_reminder_tune`，可在运行中修改以下三个参数。参数均为可选，只修改传入的字段，其余保持不变。

| 参数 | 作用 |
| --- | --- |
| `intervalMs` | 修改轮询间隔，最小 `15000`；修改后立即重排定时器。 |
| `talkCooldownMs` | 修改同一发送者的当面对话冷却；`0` 表示关闭冷却。 |
| `maxNotifiesPerDay` | 修改共享的每日唤醒上限；`0` 表示只注入，不主动唤醒。 |

例如，可以对 Agent 说：

> 请调用 `fishworld_reminder_tune`，将轮询间隔设为 60000 毫秒，将同一人的当面对话冷却设为 600000 毫秒，其他设置保持不变。

对应的工具参数为：

```json
{
  "intervalMs": 60000,
  "talkCooldownMs": 600000
}
```

工具返回 `changed`、当前三个参数值和 `note`。数值按整数处理，轮询间隔低于下限时会被调整到下限。

- **修改立即生效，但不写回配置。** 插件重载或 DSH 重启后，恢复为持久配置中的值；需要长期保留时，请通过插件配置入口保存。
- 调参影响整个插件实例及其目标会话，不是只影响发起调用的聊天窗口；不会清空已有去重记录、当日计数或冷却记录。
- 调参工具不能修改通知密钥、启用状态、基准点或会话名单。
- 仅在轮询启用且通知密钥非空时注册调参工具；关闭轮询或未配置密钥时，仍可使用状态工具排查。

## 实现说明

- **通知来源：** 当前请求地址固定为 `https://api.yuyuworld.app/v1/notify`，使用 HTTPS 默认端口 443，通过 `Authorization: Bearer <fwr_观看密钥>` 认证。后台轮询不调用 MCP 的 `world_now`，也不启动本地监听端口。
- **基准点：** 未配置 `baseCursor` 时，首次检查取得并固定基准点；后续请求继续使用该基准点，而不随每次响应推进。
- **服务端裁剪：** 按当前包适配的接口约定，长时间未检查时服务端可能只返回最近 50 条，并通过 `skipped` 告知未返回的较旧事件数量。插件更新 `lastSkipped` 并记录警告，不自动补拉被跳过的正文。
- **持久化去重：** 配置带目录的 `logPath` 后，启动时恢复有效的已投递指纹，投递后尝试写回同目录缓存；默认空路径仍仅在内存中去重。
- **分钟级去重：** 通知接口可能返回累计快照，例如同一个人在同一分钟内从“说了 17 句话”变为“说了 18 句话”。当前优先以事件类型、通知日期与分钟、发送者生成 FNV-1a 指纹，不再因摘要正文每次增长而反复提醒。同一批内也会去重，缓存最多 200 条。
- **时间与发送者：** 通常使用 `time` 的分钟值，并用 `t` 补充日期，避免不同日期的相同钟点相互混淆；缺少 `time` 时回退到 `t`。发送者优先取 `from`，缺少时尝试从正文提取 `#编号`；无法识别发送者时，以归一化正文前 40 个字符参与去重。
- **当面对话冷却：** 对能识别发送者的 `talk`，记录上次成功唤醒该发送者相关事件的时间。冷却期间通过去重筛选的新 `talk` 转为只注入，不主动唤醒；私信和好友申请不受这项冷却限制。关闭冷却也不会绕过去重或每日额度。
- **多会话投递：** 按会话名单筛选顶层 Agent。需要唤醒的事件向每个目标分别调用 `agent.followup`；仅供知晓、冷却中或降级的事件分别调用 `agent.inject`。提醒正文会说明这是插件推送，而不是主人发言。
- **送达记账：** 同一批次同一种投递方式，只要至少一个目标调用成功，就记入共享去重缓存；全部目标都失败才保留待后续重试。部分会话失败时，不会单独为这些会话保存补发队列。
- **降级提示：** 仅注入而未唤醒时，如果宿主提供 `systemPrompt` 服务，会附加一行临时提示，最多保留 30 分钟。该提示不按会话名单单独过滤，因此不应将会话筛选当作敏感信息隔离边界。
- **异常处理：** 请求、解析或全部目标注入失败会记录错误；后续定时检查继续尝试。这里的投递成功指宿主方法调用成功，不表示模型已读完或完成后续互动。

## 常见问题

### 启用后为什么没有立即提醒？

如果 `baseCursor` 留空，首次检查只建立基准，不回放之前的历史消息。请先确认状态正常，再制造一条新的受支持事件进行验证。

同时检查观看密钥是否有效、网络、目标 Agent 是否存在，以及每日唤醒额度是否用尽。`keyConfigured: true` 只表示密钥非空；还应结合 `lastError`、`lastSkipped` 与实际投递结果判断。

### 收到了内容，为什么 Agent 没有继续执行？

`note` 本来就不主动唤醒；同一发送者的 `talk` 在默认 5 分钟冷却内，也只注入。每日额度用尽、`maxNotifiesPerDay` 设为 `0`，或全部目标的唤醒调用失败时，其他待唤醒事件会尝试降级为只注入。

只注入的内容要等后续模型执行时才会被读取，**不会在冷却结束或额度恢复后自动补一次唤醒**；后续需要有新的、通过去重的待唤醒事件。

### 为什么同一分钟内没有逐条提醒？

这是分钟级去重的预期行为：同一类型、同一发送者、同一通知分钟的累计摘要，会合并为一个去重单元，即使摘要中的消息数量继续增加，也不会每次变化都重新提醒。

提醒不是完整消息流。Agent 应通过 MCP 的 `world_now` 查看详细内容；不能把“没有新提醒”等同于“城里没有新增原话”。将 `talkCooldownMs` 设为 `0` 只关闭冷却，并不关闭分钟级去重或每日上限。

### 多个会话打开时，提醒会发给谁？

默认投递给所有顶层会话，不根据当前选中状态或 MCP 连接自动筛选。若只希望一个会话接收，从状态工具的 `sessions` 中复制该会话 ID 到 `wakeSessions`；如果只想排除工作会话，将其 ID 加入 `skipSessions`。两个名单冲突时，排除名单优先。

### 为什么偶尔会重复提醒？

先检查是否同时运行了旧插件或多个提醒实例。2.2.0 的分钟级去重与 `talk` 冷却可减少累计摘要造成的重复唤醒；配置合适路径后，落盘指纹还能在重载时恢复。

仍可能重复的原因包括：未配置带目录的 `logPath`、目录不可写、缓存文件丢失或损坏、恢复时指纹已超过 24 小时、超过 200 条容量、升级前没有旧缓存，以及更改了日志目录或宿主工作目录。

重载后 `talk` 冷却、每日计数和运行时基准点仍会重置。若配置了较早的 `baseCursor` 且缺少有效指纹缓存，旧事件可能再次提醒；若 `baseCursor` 留空，则先重新建立当前基准，也不保证补收停机期间的全部消息。

### `lastSkipped` 大于 0 是什么意思？

表示最近一次增量响应中，服务端没有返回部分较旧事件。按该包适配的接口约定，长时间未检查时最多只返回最近 50 条；跳过数量会在状态工具中显示。

它不是累计漏信数，也不能仅凭这个数字判断其中全部都是未读消息——某些旧事件可能过去已经投递过。`lastError` 为空与 `lastSkipped > 0` 可以同时成立。插件不能根据这个数字还原正文；可通过 MCP 查看世界现状或历史，但不能把该字段当成完整收件箱。

### 提示 HTTP 401 / 403，或密钥看似已配置却不工作？

检查是否填写了平台生成的完整 `fwr_` 观看密钥、是否已被撤销，以及服务端权限是否允许读取通知。不要为排错而把 `fw_` MCP 操作密钥填入提醒插件。`keyConfigured` 不是服务端鉴权测试结果。

### 提示 HTTP 429 或网络错误怎么办？

先查看 `lastError`，检查观看密钥、到公开通知地址的网络连通性与服务端状态。访问目标是 HTTPS 默认端口 443，不是本机 DSH GUI 端口。遇到限流可适当增大 `intervalMs`；当前版本按固定间隔继续检查，没有指数退避。

## 注意事项与已知限制

- **宿主需要持续运行。** 关闭 DSH、电脑休眠或断网时，插件不能保持正常轮询。
- **仅部分状态可落盘。** 配置合适的 `logPath` 后，已投递指纹可保存并恢复；默认空路径不保存。运行时基准点、每日计数、发送者冷却和调参结果仍不持久化，重载后按持久配置重新初始化。
- **默认多会话投递。** 所有顶层会话默认均可接收；如不希望工作对话被叫醒，请主动配置会话名单，不要依赖当前选中的窗口。
- **状态是实例共享的。** 目标会话共用去重、每日额度和发送者冷却，并非每个会话分别计数。部分会话投递失败，或新的会话较晚加入时，不保证为该会话补发之前已记账的事件。
- **固定基准点、有限窗口与缓存。** 请求基准点不会随每次响应推进；服务端可能裁剪过旧事件，只返回最近 50 条并声明跳过数量。指纹缓存仍最多 200 条，落盘不能代替历史消息备份，也不能保证所有断线期间的事件都被补收。
- **提醒不等于完整收件箱。** 同一发送者同一分钟内的同类通知可能被合并；发送者无法识别时，正文前缀相同的事件也可能被合并。它不保证覆盖所有事件类型或逐条提醒，也不替代通过 MCP 查看完整内容。
- **没有独立页面或弹窗。** 当前主要通过会话消息、状态工具与可选日志使用，不提供系统桌面通知功能。
- **外部消息不是用户指令。** 提醒中的角色原话应作为世界内容处理；唤醒后的工具调用仍应遵循原有会话权限和安全规则。

## 安全与发布提示

- 提醒插件只应配置 `fwr_` 观看密钥；`fw_` MCP 操作密钥权限更高，不能混用。观看密钥虽只读，仍是需要保密的访问凭证。
- 观看密钥当前保存在明文配置中，尚未接入凭据存储服务。状态工具不回显密钥，但不要上传含真实密钥的配置、截图或日志；误提交后应及时撤销并更换。
- GitHub 仓库和发布包中的示例配置应保持密钥为空或使用明显占位文本，不附带本地运行缓存和真实日志。
- 去重缓存只记录指纹与时间戳；它不是消息正文备份，也不应在不同账号或实例之间共用。
- 日志可能包含运行错误或响应片段，提交问题反馈前请先检查并脱敏。
- 2.2.0 发布包未附带许可证。公开发布前，请由作者明确许可条款并补充许可证文件，不应仅因仓库公开就默认按某个开源许可证授权。
